# 幼麟四川麻将逻辑参考记录

参考仓库：<https://github.com/babykylin/babykylin_scmj>

本项目将参考仓库作为只读设计样本，不直接复制四川麻将玩法。实际实现始终以 `docs/GAME_RULES.md` 中已经确认的本地规则为准。

## 已采用的通用设计

- 服务端保存权威牌局状态，客户端只提交操作意图。
- 开局时每名玩家只收到自己的具体手牌，公共广播只包含座位、手牌数量和牌桌公共信息。
- 重连时按玩家身份恢复其个人手牌，不把其他玩家手牌放入同步数据。
- 出牌必须由服务端校验当前轮次、操作阶段和玩家是否真实持有该牌。
- 成功弃牌作为公共信息广播，并在服务端进入独立响应阶段，为后续操作优先级留出边界。
- 当前响应候选为空时由服务端立即推进到下一家摸牌；客户端不自行修改轮次或牌墙。
- 测试玩家自动摸打也完全在服务端执行，并通过普通公开快照同步，保证真人与测试回合使用同一套状态。
- 弃牌候选仅通过个性化快照下发；公共状态只公开待响应数量，不公开具体资格座位，也不泄露其他玩家可吃、可碰或可胡的内容。
- 多人响应由服务端收齐后统一按胡、杠、碰、吃裁决；胡保留多赢家集合，其余操作只落地最高优先级的一项。
- 吃碰明杠成立后由服务端移除具体手牌和被取用弃牌、生成公开副露，并决定直接出牌或从牌墙尾部补牌。
- 自摸、暗杠和加杠候选也只通过当前玩家的个性化快照下发，客户端不能自行声明服务端未计算出的操作。
- 加杠先建立只允许胡或过的抢杠窗口；全过后再升级原碰牌并杠尾补牌，被抢时保留原碰牌。
- 特殊杠和每次涨毛沿用同一个服务端抢杠边界，但各自独立暂存牌张、收齐响应、确认副露并从牌墙尾部补牌。
- 暗杠的真实牌面保留在服务端权威状态和本人快照中，公共快照只公开四张隐藏牌数量。
- 每笔胡分和杠分都由服务端生成权威支付记录，再统一累加到本局分差和房间累计分；客户端只展示结算快照，不自行计算分数。
- 下一局局数和庄位由服务端根据上一局公开结果推进；客户端只能由房主提交开始意图，不能自行指定庄家或重置累计分。
- 整场模式、完成局数、结束原因和最终排名均由服务端权威维护；客户端只在创建时选择8/16局并展示快照，不能自行宣布整场结束或修改排名。
- 提前结算沿用服务端权威响应状态机：申请、每个座位的表态和结果进入公共房间快照，断线重连可恢复；客户端只能提交同意或拒绝意图。
- 每局结束时固化局数、庄位、赢家、分差与累计分作为只读历史，后续操作回放可以在该快照边界上继续扩展。

## 明确不采用的内容

- 参考项目使用108张四川麻将牌，本项目使用万、筒、条和七种字牌共136张。
- 参考项目不包含“吃”，本项目必须实现下家吃牌。
- 不采用参考项目的换三张、定缺、血战到底和四川番型结算。
- 不采用其 `Math.random` 洗牌；本项目使用加密随机数驱动的 Fisher–Yates 洗牌。
- 不直接迁移旧 Socket.IO 协议、数据库结构和客户端 Cocos 组件。

## 后续可继续参考的边界

- 操作记录、牌局回放和结算快照的分层方式。

这些边界只参考状态机拆分思路；吃碰杠胡条件、过胡规则、特殊杠与涨毛、计分和整场结算均按本项目规则重新实现并测试。
